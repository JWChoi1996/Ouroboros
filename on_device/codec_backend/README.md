# Ouroboros H.264 instrumentation backend

This directory pins FFmpeg `n8.0.1` (commit
`894da5ca7d742e4429ffb2af534fcda0103ef593`) and applies an internal decoder
instrumentation patch. Build it under WSL Ubuntu:

```bash
on_device/codec_backend/build_backend.sh
make -C on_device/custom_h264 clean all
```

The custom `AV_FRAME_DATA_OUROBOROS_H264_RESIDUAL` side data is generated by
the decoder. It is **not H.264 SEI content**. Version 2 contains signed
pixel-domain Y/U/V effective residuals, valid masks, optional prediction and
pre-filter validation planes, and a separate 10-column transform-coefficient
summary.

The exact residual convention is:

```text
effective residual = pre-filter reconstruction - prediction
```

It is captured after normative IDCT-add clipping and before deblocking.
Version 2 supports one-thread, 8-bit YUV420P, progressive I/P streams only;
IPCM macroblocks remain invalid in the masks. B-frames, multiple references,
threaded decode, high bit depth, and H.265 are outside the supported scope.

Generated source, objects, libraries, the self-test executable, and the build
manifest are ignored by Git.
